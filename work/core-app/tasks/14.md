## Details

**What to audit:**

**Unit test completeness:**
- `test_scorer.py`: all tier combinations? empty answer edge cases? boundary scores?
- `test_grader.py`: malformed JSON → error? null variant? all-empty answers → unreadable?
- `test_criteria_loader.py`: path traversal blocked? filename/content mismatch?
- `test_exporter.py`: PENDING/ERROR markers? unreadable excluded? grade 2 blank level? sort order?
- `test_db.py`: UNIQUE constraint? WAL mode? metadata lock?

**Integration test completeness:**
- Full pipeline with real Drive: all student statuses covered
- Resumability: pre-seeded students skipped, no duplicate rows
- Drive error path: download failure → error status distinct from unreadable

**Fixture quality:** LLM response fixtures realistic? Cover low/high confidence? null variant? all 16 tasks?

**Test pyramid balance:** Too many integration tests? Too few unit tests?

**Test isolation:** Unit tests truly independent (no shared state, no real API calls)?

**What to produce:**

Write a markdown report to `work/core-app/logs/test-audit.md` with:
- Coverage summary (what's tested well, what's missing)
- Findings (severity: critical / warning / info)
- Missing test recommendations with specific test names
