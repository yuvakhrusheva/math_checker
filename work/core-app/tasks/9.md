# Task 9: Main screen UI (cohort queue)

## Required Skills

Before executing this task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Build the Main Streamlit page for managing the cohort processing queue. The page provides the full operator workflow: viewing all cohorts with live statuses, adding new cohorts via a form with validation, editing/deleting pending cohorts, starting the processing queue, and watching live progress updates without full page reloads.

Interface text must be in English (CA-28). The page supports CA-4 through CA-9 of the user spec.

## What to do

- Create `pages/main.py` as the full Streamlit page with:
  - Cohort queue table showing all cohorts (School, Class, Teacher, Test Date, Language, Status, PDFs, Actions)
  - Edit and Delete actions visible only for cohorts with status=pending
  - Add Cohort form (inside expander or st.form) with all required fields and validation
  - Start Processing button, disabled when `queue_processor.is_running()` returns True
  - Live progress section using `@st.fragment(run_every=2)` polling SQLite for updates
- Register ALL four pages in `app.py` via `st.navigation` (T9 is the sole owner of app.py in Wave 5):
  - `pages/criteria_management.py` (created in T8)
  - `pages/main.py` (created in T9)
  - `pages/review_panel.py` (created in T10)
  - `pages/export.py` (created in T11)
- Note: T10 and T11 only create their respective page files — app.py registration is T9's responsibility

## Details

**Files:**
- `pages/main.py` — full Streamlit page (create)
- `app.py` — register ALL four pages in st.navigation (modify): criteria_management (T8), main (T9), review_panel (T10), export (T11). T9 is the sole owner of app.py in Wave 5; T10 and T11 do not touch app.py.

**UI layout:**

```
Page: Main — Cohort Queue

[Cohort Queue Table]
  Columns: School | Class | Teacher | Test Date | Language | Status | PDFs | Actions
  Status: Pending (editable) | Processing | Done | Done with errors
  Actions (only for Pending): Edit | Delete

[Add Cohort]
  st.expander("Add Cohort") or st.form():
    - GDrive folder URL (text_input)
    - School (text_input)
    - Class number (number_input, 1-11)
    - Class letter (text_input, e.g. "A")
    - Teacher name (text_input)
    - Test date (date_input)
    - Language (selectbox: ru / az)
    - Grade (selectbox: 2 / 3)
  On submit:
    - validate criteria_loader.criteria_exists(grade, language) → show error if not
    - call db.create_cohort(...)
    - st.rerun()

[Start Processing button]
  st.button("Start Processing", disabled=queue_processor.is_running())
  On click: queue_processor.start()

[@st.fragment(run_every=2) — progress section]
  Show live status of each cohort
  Progress bars per cohort in processing state
  Student counts: total / processed / requires_review / error
```

**Edge cases:**
- GDrive URL: validate it contains "drive.google.com" before submitting
- Edit form: pre-populate with existing cohort data; on save call db.update_cohort_metadata()
- Language options: "ru" (Russian), "az" (Azerbaijani)
- Criteria check (CA-5): call criteria_loader.criteria_exists(grade, language) on form submit; show st.error and do not add cohort if missing
- Edit/Delete buttons must check status at render time — do not show for non-pending cohorts

**Implementation hints:**
- Use `@st.fragment(run_every=2)` decorator on the progress/status section to avoid full page reloads
- Read `src/db.py`, `src/queue_processor.py`, and `src/criteria_loader.py` before writing any code to understand available APIs
