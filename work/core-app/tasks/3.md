# Task 3: Criteria JSON schema and loader

## Description

Implement `src/criteria_loader.py` — the module responsible for loading, validating, saving, and listing criteria files used by the grading system.

Each criteria file follows the naming convention `grade{2|3}_{ru|az}_v{1|2}.json` (e.g. `criteria/grade3_ru_v1.json`). When a file is uploaded (via the Criteria Management UI in a future task), it must be validated in two ways:
1. The filename must match the expected pattern.
2. The internal `grade`, `language`, and `variant` fields in the JSON must match what the filename says — reject with a clear error if mismatched.

Path traversal protection is required: the resolved write path must stay within the `criteria/` directory.

The 4 initially-available criteria files are created by the operator via the Criteria Management UI before first use — this task only provides the loader/validator and schema, not the file content.

## What to do

- Create `src/criteria_loader.py` with all five functions listed below.
- Create `tests/unit/test_criteria_loader.py` with the TDD anchors listed below.
- Follow TDD: write tests first, confirm they fail, implement, confirm they pass.
- Auto-create `criteria/` directory if it does not exist.
- Validate filename format with a regex before attempting JSON parse.
- After validating filename, parse JSON and cross-check `grade`, `language`, `variant` fields against filename-derived values.
- In `save_criteria_file`, resolve the absolute path and assert it starts with the absolute path of `criteria/` before writing.

### Functions to implement

- `load_criteria(grade: int, language: str, variant: int) -> dict` — construct filename, load and return parsed dict; raise FileNotFoundError if missing.
- `validate_criteria_file(filename: str, content: bytes) -> dict` — validate filename format AND that internal fields match filename; return parsed dict or raise `ValueError` with a descriptive message.
- `save_criteria_file(filename: str, content: bytes) -> Path` — call `validate_criteria_file`, then write to `criteria/`; enforce path-traversal protection; return resolved Path.
- `list_available_combinations() -> list[dict]` — scan `criteria/` for valid `.json` files matching the naming pattern; return list of `{"grade": int, "language": str, "variant": int}`.
- `criteria_exists(grade: int, language: str) -> bool` — return True if at least one variant exists for the given grade+language combo.

## Details

**Note:** The criteria JSON files (e.g. `criteria/grade2_ru_v1.json`, `criteria/grade3_ru_v1.json`, etc.) are **not** created by this task. They are created by the operator via the Criteria Management UI before first use. This task only provides the loader, validator, and schema definition.

**Schema reference:**

Filename: `criteria/grade{2|3}_{ru|az}_v{1|2}.json`

```json
{
  "grade": 3,
  "language": "ru",
  "variant": 1,
  "total_max_score": 100,
  "tasks": [
    {
      "task_number": 1,
      "description": "Order numbers ascending",
      "max_score": 4,
      "tiers": [
        {"score": 4, "label": "full", "condition": "All four numbers in correct ascending order"},
        {"score": 0, "label": "zero", "condition": "Any number out of order or missing"}
      ],
      "correct_answers": ["93, 309, 390, 930"],
      "answer_type": "ordered_list"
    }
  ]
}
```

**Edge cases:**
- `criteria/` directory doesn't exist yet — create it on first write
- File with valid name but invalid JSON content → raise ValueError
- Path traversal: `../../.env`, `../criteria/../../secret` → raise ValueError
- Empty `criteria/` directory → `list_available_combinations` returns `[]`

**Implementation hints:**
- Use `re.fullmatch` with pattern `grade[23]_(ru|az)_v[12]\.json` for filename validation
- Parse grade/language/variant from filename using the regex groups
- Use `Path(resolved_path).is_relative_to(Path('criteria').resolve())` for path traversal protection — more robust than string prefix checking
- Use `json.loads(content)` to parse bytes; wrap in try/except for invalid JSON
