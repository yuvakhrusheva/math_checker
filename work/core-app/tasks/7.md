# Task 7: Queue processor with background threading

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Implement the background queue processor that drives the full student grading pipeline. `src/queue_processor.py` must expose a `ProcessingThread` (daemon thread) that picks up pending cohorts from SQLite one at a time, runs each student through the drive → pdf_processor → grader pipeline, and updates statuses in real time. Module-level `start()`, `is_running()`, and `request_stop()` functions let the UI (and integration tests) control the thread without direct access to the thread object. Error messages written to the DB must be sanitized to prevent API key or token leakage.

## What to do

1. Create `src/queue_processor.py` with `ProcessingThread(threading.Thread)` (daemon=True, uses `threading.Event` for stop flag).
2. Implement `run()`: loop over pending cohorts via `db.get_next_pending_cohort()`; for each cohort iterate students sequentially through the pipeline; check stop flag between students.
3. Implement per-student pipeline steps in order: set status=processing → download PDF → convert to images → grade → determine final status → save results → set final status. Handle each failure mode (download error, UnreadablePDFError, JSONDecodeError) with the correct status.
4. Implement resumability: before processing a student, re-fetch their status from DB and skip if not 'pending'.
5. Implement error message sanitization: redact `sk-...` / `AIza...` patterns and base64-like sequences longer than 40 chars with `[REDACTED]` before writing to `students.error_message`.
6. Expose module-level singleton functions: `start()`, `is_running()`, `request_stop()`.
7. Write integration tests in `tests/integration/test_queue_processor.py` covering all TDD anchors below (write tests first, confirm they fail, then implement).

## Details

**Files:**
- `src/queue_processor.py` — create: ProcessingThread class + module-level singleton API
- `tests/integration/test_queue_processor.py` — create: integration tests for all pipeline scenarios

**Dependencies:** Tasks 4 (db schema), 5 (drive.py), 6 (grader.py) must be complete before this task starts.

**Edge cases:**
- Stop flag checked between students, not between pipeline steps (current student always finishes)
- If cohort has no pending students, loop continues to next cohort (or exits if none)
- Sanitization must run even when exception message is empty or None
- `start()` is idempotent: no-op if thread is already alive

**Implementation hints:**
- Use `re.sub` with compiled patterns for sanitization; keep the function pure and unit-testable separately
- `daemon=True` is set in `__init__` via `super().__init__(daemon=True)`, not as a property setter
- Integration tests should use a real (test) SQLite DB and may mock Drive/LLM calls for speed, but `test_full_pipeline_5_students` uses real Drive
- The stop flag is a `threading.Event`; check with `self._stop_flag.is_set()` at the top of the while loop

```python
import threading

class ProcessingThread(threading.Thread):
    def __init__(self):
        super().__init__(daemon=True)
        self._stop_flag = threading.Event()

    def run(self):
        while not self._stop_flag.is_set():
            cohort = get_next_pending_cohort()  # from db
            if cohort is None:
                break
            self._process_cohort(cohort)

    def request_stop(self):
        self._stop_flag.set()

# Module-level singleton
_thread: ProcessingThread | None = None

def start():
    global _thread
    if _thread is None or not _thread.is_alive():
        _thread = ProcessingThread()
        _thread.start()

def is_running() -> bool:
    return _thread is not None and _thread.is_alive()

def request_stop():
    if _thread:
        _thread.request_stop()
```

**Student pipeline (per PDF):**
1. `db.update_student_status(student_id, 'processing')`
2. Download: `drive.download_pdf(...)` → if fails: set status=error, error_message=sanitized exception, continue
3. Convert: `pdf_processor.pdf_to_images(path)` → if UnreadablePDFError: set status=unreadable, continue
4. Grade: `grader.grade_student(images, criteria)` → if JSONDecodeError: set status=error, continue
5. Determine final status: `requires_review` (confidence:low or null variant) or `processed`
6. Save task_results to DB
7. `db.update_student_status(student_id, final_status)`

**Error message sanitization patterns:**
- API keys: `sk-[A-Za-z0-9]+`, `AIza[A-Za-z0-9_-]+`
- Long base64-like sequences: `[A-Za-z0-9+/=]{40,}`
- Replace all matches with `[REDACTED]`
