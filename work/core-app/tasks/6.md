# Task 6: LLM grader and scoring engine

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Implement two core modules that power the AI-grading pipeline:

- `src/scorer.py` — pure deterministic score computation. Given a recognized answer string and a task's criteria (tiers), returns a (score, notes) tuple. No LLM calls, no I/O — fully deterministic and unit-testable in isolation.
- `src/grader.py` — orchestrates the LLM grading call. Builds a multi-image LiteLLM prompt from criteria JSON, calls the vision model, parses the response JSON, delegates scoring to scorer.py, and returns a structured result dict. Also determines student status (requires_review, unreadable) from the LLM response fields.

Both modules require fixture-based unit tests (no real LLM calls in unit tests).

## What to do

1. Implement `src/scorer.py` with `compute_score(recognized_answer, task_criteria) -> tuple[float, str]` handling numeric, ordered_list, and text answer types across full/partial/zero tiers.
2. Implement `src/grader.py` with `build_prompt(criteria, pages)` and `grade_student(pages, criteria)` functions using LiteLLM for the vision model call.
3. Create `tests/fixtures/llm_responses/sample_response.json` with 16 realistic tasks (mix of high/low confidence).
4. Write `tests/unit/test_scorer.py` with fixture-based tests covering all answer types and edge cases.
5. Write `tests/unit/test_grader.py` with fixture-based tests covering prompt structure, response parsing, error propagation, and status flags.

**Note on scorer.py vs grader.py responsibilities:** `scorer.py`'s `compute_score` takes only `(recognized_answer, task_criteria)` — `confidence` is **not** a parameter of scorer.py. `scorer.py` purely computes the numeric score from the answer string and tier conditions. It is `grader.py` that handles confidence-based routing: after delegating to scorer.py, grader.py reads the `confidence` field from the LLM response and sets the student's status to `requires_review` when confidence is low.

**grader.py LiteLLM call:**
```python
import litellm
import json

def grade_student(pages: list[tuple[int, str]], criteria: dict) -> dict:
    """pages: list of (page_number, base64_jpeg). Returns parsed LLM response dict."""
    prompt = build_prompt(criteria, pages)
    response = litellm.completion(
        model=settings["model"],
        messages=[
            {"role": "system", "content": "You are a math grader for Azerbaijani school students..."},
            {
                "role": "user",
                "content": [
                    {"type": "text", "text": prompt},
                    *[{"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}} for _, b64 in pages]
                ]
            }
        ],
        max_tokens=settings["max_tokens"],
        temperature=settings["temperature"]
    )
    # Note: the system prompt is always the first message (role="system"), separate from the
    # user message that carries the images and per-task prompt text.
    raw = response.choices[0].message.content
    return json.loads(raw)  # raises json.JSONDecodeError if unparseable
```

**Expected LLM output structure:**
```json
{
  "recognized_student_name": "Иванов Иван",
  "detected_variant": 1,
  "tasks": [
    {
      "task_number": 1,
      "page_number": 1,
      "recognized_answer": "93, 309, 390, 930",
      "score": 4,
      "max_score": 4,
      "confidence": "high",
      "notes": "All numbers in correct order"
    }
  ]
}
```

**System prompt for LLM:** "You are a math grader for Azerbaijani school students. Read the handwritten math test shown in the images. For each task, identify the student's answer, compare it to the criteria, and return a JSON response only (no additional text)."

**Student status determination:**
- `detected_variant` is null → student status = `requires_review`
- Any task has `confidence: low` → student status = `requires_review`
- All tasks have empty `recognized_answer` AND `confidence=high` → student status = `unreadable`
- `json.JSONDecodeError` → caller (queue_processor) sets status = `error`

**Edge cases:**
- recognized_answer is None vs empty string — both treated as "no answer"
- LLM returns valid JSON but missing expected fields — handle gracefully
- All 16 tasks in fixture must be realistic Azerbaijani school math content
- Mock litellm.completion in unit tests to avoid network calls
