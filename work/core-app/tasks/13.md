# Task 13: Security Audit

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:security-auditor` — [skills/security-auditor/SKILL.md](~/.claude/skills/security-auditor/SKILL.md)

## Description

Full-feature security audit of the core-app codebase. Review for secrets in code or logs, path traversal in file download/storage, GDrive URL parsing safety, SQLite injection risks, and criteria JSON validation robustness. Write a structured report to `work/core-app/logs/security-audit.md`.

## What to do

Audit the following OWASP Top 10 focus areas across all security-relevant source files:

- **A01 Broken Access Control:** PDF file access in review panel — verify paths stay within `data/downloads/`
- **A03 Injection:** Confirm SQLite parameterized queries everywhere; no string formatting into SQL; check criteria JSON field length limits
- **A05 Security Misconfiguration:** Verify `drive.readonly` scope is enforced in code; confirm service account key path is validated at startup
- **A06 Vulnerable Components:** PyMuPDF processes untrusted PDFs (CVE history) — identify any existing mitigations
- **A09 Security Logging Failures:** Check error messages in DB/UI for API key or token leakage; verify sanitizer covers all key formats (`sk-`, `AIza-`, `Bearer`, OAuth tokens)
- **Secrets scan:** Check for any hardcoded keys or tokens in source; confirm gitleaks config covers all secret patterns
- **File upload security:** Validate that criteria JSON upload — content is validated before write, filename is validated

## Acceptance Criteria

## Details

**What to produce:** Write a markdown report to `work/core-app/logs/security-audit.md` with:
- Executive summary
- Findings by OWASP category (severity: critical / warning / info, file:line)
- Recommended fixes

**Secrets scan command:** `gitleaks detect --source . --verbose`

**Files to audit:**
- `src/drive.py` — GDrive URL parsing, OAuth scope enforcement, service account key path validation
- `src/db.py` — SQLite query parameterization, no string interpolation into SQL
- `src/criteria_loader.py` — JSON upload content validation, filename validation, field length limits
- `src/queue_processor.py` — error message sanitization, token/key leakage in logs
- `pages/review_panel.py` — PDF file path traversal, access control within `data/downloads/`
- `app.py` — startup configuration validation, secrets exposure

**Edge cases:**
- Sanitizer must cover all key formats: `sk-`, `AIza-`, `Bearer`, OAuth tokens
- Path traversal: verify symlink and `../` escapes are blocked for PDF downloads
- PyMuPDF: check if untrusted PDF processing has any sandboxing or size limits
