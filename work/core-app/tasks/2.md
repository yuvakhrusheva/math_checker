## Description

Implement the full SQLite database layer for math_checker. This module (`src/db.py`) is the single source of truth for all persistent data: cohorts (test sessions), students (individual answer sheets), and task_results (per-task grading outcomes). Every other module reads and writes through this layer — it must be correct, safe, and concurrent-friendly.

Key constraints:
- All queries must use parameterized statements — never string-format user input into SQL.
- WAL mode must be enabled on every connection to handle concurrent access from Streamlit UI and background processing threads.
- `init_db()` must be idempotent (safe to call multiple times on startup).
- `update_cohort_metadata` must raise an error if the cohort is not in `pending` status.

## What to do

- Create `src/db.py` with:
  - `init_db()` — run `CREATE TABLE IF NOT EXISTS` for all 3 tables using exact DDL from the schema below, then `PRAGMA journal_mode=WAL`

## Details

**Files:**
- `src/db.py` — full implementation (schema + all CRUD functions)
- `tests/unit/test_db.py` — unit tests

**SQLite schema (exact DDL):**

```sql
CREATE TABLE cohorts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    gdrive_folder_url TEXT NOT NULL,
    gdrive_folder_id TEXT NOT NULL,
    school TEXT NOT NULL,
    teacher TEXT NOT NULL,
    class_number INTEGER NOT NULL,
    class_letter TEXT NOT NULL,
    in_project INTEGER NOT NULL DEFAULT 1,
    language TEXT NOT NULL CHECK(language IN ('ru', 'az')),
    test_date TEXT NOT NULL,
    grade INTEGER NOT NULL CHECK(grade IN (2, 3)),
    status TEXT NOT NULL DEFAULT 'pending'
        CHECK(status IN ('pending', 'processing', 'done', 'done_with_errors'))
);

CREATE TABLE students (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    cohort_id INTEGER NOT NULL REFERENCES cohorts(id),
    gdrive_file_id TEXT NOT NULL,
    filename TEXT NOT NULL,
    recognized_name TEXT,
    detected_variant INTEGER,
    status TEXT NOT NULL DEFAULT 'pending'
        CHECK(status IN ('pending', 'processing', 'processed',
                         'requires_review', 'unreadable', 'error')),
    review_status TEXT CHECK(review_status IN ('pending', 'done')),
    error_message TEXT,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE task_results (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id INTEGER NOT NULL REFERENCES students(id),
    task_number INTEGER NOT NULL,
    page_number INTEGER NOT NULL,
    recognized_answer TEXT,
    score REAL NOT NULL DEFAULT 0,
    max_score REAL NOT NULL,
    confidence TEXT NOT NULL CHECK(confidence IN ('low', 'high')),
    grading_notes TEXT,
    manually_corrected INTEGER NOT NULL DEFAULT 0,
    UNIQUE(student_id, task_number)
);
```

**CRUD functions:**
- `init_db()` — CREATE TABLE IF NOT EXISTS for all 3 tables, then PRAGMA journal_mode=WAL
- Cohorts: `create_cohort(...)`, `get_cohort(id)`, `list_cohorts()`, `update_cohort_status(id, status)`, `update_cohort_metadata(id, **fields)` — raises ValueError if cohort status != pending
- Students: `create_student(cohort_id, gdrive_file_id, filename)`, `get_student(id)`, `list_students_by_cohort(cohort_id)`, `update_student_status(id, status, error_message=None)`, `update_student_variant(id, detected_variant)`, `update_student_recognized_name(student_id: int, name: str)`, `list_requires_review()`
- Task results: `save_task_result(student_id, task_number, ...)` — use `INSERT OR REPLACE INTO task_results` (or equivalent upsert) — if a row with same (student_id, task_number) exists, replace it. This ensures idempotency for resumable processing. `get_task_results(student_id)`, `update_task_result(id, recognized_answer, score, manually_corrected=True)`

**Dependencies:** Task 1 (project structure must exist before adding src/db.py)

**Edge cases:**
- Concurrent access from background thread and Streamlit UI — WAL mode handles this
- init_db() called multiple times (must be idempotent — use CREATE TABLE IF NOT EXISTS)
- update_cohort_metadata called on non-pending cohort — must raise ValueError or similar

**Implementation hints:**
- Use a single `get_connection()` helper that always sets `PRAGMA journal_mode=WAL` and `row_factory = sqlite3.Row` for dict-like row access
- Use `CREATE TABLE IF NOT EXISTS` in init_db() for idempotency
- In `update_cohort_metadata`, fetch the cohort first, check status, raise ValueError before executing any UPDATE
