# Task 4: Google Drive integration

## Description

Implement Google Drive integration for downloading student test PDFs. The module `src/drive.py` authenticates with a Google service account (read-only scope), extracts folder IDs from GDrive URLs, lists all PDFs in a folder (with pagination), and downloads them to `data/downloads/{cohort_id}/`. This is the data-ingestion layer: it feeds PDFs to the grading pipeline.

Security and reliability requirements are strict: filenames from Drive must be sanitized before writing to disk (path traversal prevention), download failures must be captured as error info rather than raised exceptions (so the queue processor can log them to the student record per CA-14), and rate-limit errors must be retried with exponential backoff.

## What to do

- Create `src/drive.py` with four functions: `get_service`, `extract_folder_id`, `list_pdfs`, `download_pdf`
- Authenticate using service account credentials file path from `GOOGLE_SERVICE_ACCOUNT_JSON` env var, scope `drive.readonly` only
- Extract folder ID from both GDrive URL formats (with and without `/u/0/`)
- List all PDFs in folder using Files API with pagination support
- Download each PDF using `MediaIoBaseDownload`, save to `data/downloads/{cohort_id}/{sanitized_filename}`
- Sanitize filenames: `os.path.basename`, strip path separators, replace dangerous characters
- On 429 or `rateLimitExceeded` HttpError: retry up to 3 times with exponential backoff (0.5s → 1s → 2s)
- On download failure: return `None` and error info dict (do not raise), so caller can set `student.status=error` with `error_message`
- Create `tests/integration/test_drive.py` with integration tests (real Drive via TEST env vars) and unit tests for URL parsing and filename sanitization

## Details

**Files:**
- `src/drive.py` — full implementation of all four functions
- `tests/integration/test_drive.py` — integration tests (real Drive test account) + unit tests for URL parsing and sanitization

**Auth implementation:**
- `google.oauth2.service_account.Credentials.from_service_account_file(path, scopes=['https://www.googleapis.com/auth/drive.readonly'])`
- `googleapiclient.discovery.build('drive', 'v3', credentials=creds)`

**Folder ID extraction:**
- URL formats: `https://drive.google.com/drive/folders/{FOLDER_ID}` and `https://drive.google.com/drive/u/0/folders/{FOLDER_ID}`
- Use regex or `urllib.parse` to extract the ID segment

**List PDFs:**
- Query: `f"'{folder_id}' in parents and mimeType='application/pdf'"`
- Fields: `files(id, name, size)`
- Handle `nextPageToken` for pagination

**Download:**
- `service.files().get_media(fileId=file_id)` + `MediaIoBaseDownload`
- Sanitize filename: `os.path.basename(name)`, strip `/`, `\`, replace `..`

**Rate limit resilience:**
- Catch `HttpError` with status 429 or reason `rateLimitExceeded`
- Retry delays: 0.5s, 1s, 2s (max 3 retries)

**Error handling (CA-14):**
- Download failure → do NOT raise; return `None` and error dict `{"file_id": ..., "error": str(e)}`
- Caller (queue_processor) sets `student.status = "error"` and `student.error_message` from this info
- Drive errors are logged separately from LLM/grading errors

**Edge cases:**
- Folder with 0 PDFs → return empty list
- Filename from Drive contains `/` or `..` → sanitized
- Rate limit hit → retry, succeed on retry
- Drive API quota exceeded after retries → return failure (not exception)
